## Пользовательские действия в CMS (после внедрения)
1. `/admin` → **Website CMS → Page texts** → выбрать страницу RU/TM/EN и читаемый текстовый блок.
2. Написать текст, сохранить черновик, проверить корректность перевода, включить **Published on website**.
3. **Website CMS → Photos and videos** → выбрать раздел и позицию, загрузить JPG/PNG/WebP либо MP4/WebM.
4. Для видео приложить обложку и подписи; сохранить как черновик, проверить, затем опубликовать.
5. Для замены: открыть существующую позицию, выбрать новый файл, сохранить; исходный файл остаётся в хранилище. Для отката публикации выключить переключатель и вернуть исходное изображение страницы/галереи.
6. Данные CRM, сведения о клиентах и коды отслеживания не изменять из редакторов CMS.

## HTTP безопасность
- В live HTTPS ответе /admin/login есть Secure/HttpOnly/SameSite cookie. Однако отсутствовали `X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy`, `Strict-Transport-Security` и CSP.
- Код новой CMS добавляет консервативные `X-Frame-Options: SAMEORIGIN`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin` для Laravel-ответов. Статические файлы nginx надо настраивать на уровне хостинга.
- HSTS **по умолчанию выключен**, до окончательной проверки HTTPS/rollback. При включении только для HTTPS первичный `max-age=86400`, **без** includeSubDomains/preload. CSP вводить отдельно в Report-Only с тестами Filament/Livewire.
